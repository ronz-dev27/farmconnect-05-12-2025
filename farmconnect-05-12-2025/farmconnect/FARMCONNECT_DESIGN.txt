Core users: farmers (primary), buyers/aggregators (secondary), administrators (manage data & reports), and guests (informational + demo requests).

Active-class logic (server-side sample):
<?php
$menu = ['index.php'=>'Home','about.php'=>'About', ...];
foreach($menu as $file=>$label){
  $active = basename($_SERVER['PHP_SELF'])===$file ? 'active' : '';
  echo "<li class=\"nav-item\"><a class=\"nav-link $active\" href=\"$file\">$label</a></li>\n";
}
?>

10. Database Schema
(Use MySQL / MariaDB)
Tables:
- users
  - id PK, name, email (unique), password_hash, role (enum: farmer,buyer,admin), phone, created_at, updated_at
- demo_requests
  - id PK, user_id nullable, name, org, phone, email, location, preferred_datetime, notes, status, created_at
- messages
  - id PK, name, email, phone, subject, message, ip, created_at
- features (optional CMS)
  - id, title, summary, content, image_path, created_at
- market_prices
  - id, commodity, market_name, price, unit, recorded_at, source
- alerts
  - id, alert_type, title, details, region, severity, publish_at
- reports (meta)
  - id, report_type, title, file_path, created_at
- logs (or use app logs)
  - id, event_type, payload JSON, created_at

11. API Endpoints (brief)
- GET /api/v1/weather?lat=&lon= -> localized forecast
- GET /api/v1/markets?location= -> nearby market prices
- GET /api/v1/buyers?query= -> buyer directory
- POST /api/v1/contact -> submit contact
- POST /api/v1/demo -> submit demo request
- GET /api/v1/features -> feature list
- Auth endpoints (POST /api/v1/login, POST /api/v1/logout)

12. Security & Validation Checklist
- Use parameterized queries (PDO prepared statements) to prevent SQL injection.
- Validate & sanitize all inputs (filter_var, regex) and escape output (htmlspecialchars).
- CSRF protection: add tokens to forms and validate on submit.
- Password hashing: password_hash/password_verify (bcrypt/argon2).
- HTTPS: enforce HTTPS in production and HSTS header.
- File uploads: restrict mime types, size limits, store outside webroot or with randomized names.
- Rate limiting for forms (simple throttle by IP) to limit spam.
- Access control: restrict admin pages by role.
- Logs: store sensitive logs securely; do not log passwords.

13. Accessibility & Performance Checklist
Accessibility:
- Use semantic HTML (header, nav, main, footer, section, h1..h6)
- Provide alt text for images.
- Ensure keyboard navigation (focus states for menu and buttons).
- aria-expanded on hamburger and aria-controls linking to slide-out menu.
- Contrast ratios >= WCAG AA for text vs background.
- Use skip-to-content link at top.
Performance:
- Serve compressed assets (gzip/ brotli via server config).
- Use optimized images (SVGS for icons; webp for photos where possible).
- Minify CSS/JS for production; use caching headers.
- Lazy-load below-the-fold images.
